# 编译期内置统一密码，而非零认证

Status: accepted

最初诉求是"拿到 IP 就能连、完全免认证"。评估后认为不可接受：零认证意味着内网中任何人或恶意程序都能完全控制所有业务机器（键鼠、文件、剪贴板）。采用折中方案——编译期把统一密码烧入二进制，控制端连接时自动携带，用户体验与免密完全一致，但外部客户端和扫描器无法接入。同时补齐 hoptodesk 中仅有 UI、无后端强制的 IP 白名单，默认放行内网段。

## Considered Options

- 完全零认证：因内网横向移动风险被否决。
- 每台机器单独设固定密码：运维负担大，IT 需维护密码清单，被否决。

## Consequences

- 密码泄露等于全网泄露，需要换密码时必须重新编译发布，更新机制（手动覆盖安装）放大了这一成本。
- 内置密码可被逆向提取，它防的是随意接入，不是定向攻击；白名单是第二道防线。
